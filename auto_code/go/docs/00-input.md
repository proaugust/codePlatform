# 需求结论（澄清确认）

## 摘要
在 Go net/http 图书服务中新增删除图书接口，前端页面可选择要删除的图书并调用后端完成删除；后端同时托管静态页面，默认监听 8080，前端通过 http://localhost:8080/ 访问。

## 目标
- 提供删除图书的 HTTP 接口，支持按图书标识删除指定图书
- 前端页面可选择某一本图书并触发删除，后端执行删除并返回结果
- 明确前端启动方式与访问地址：由后端在 8080 端口托管静态页面，访问 http://localhost:8080/

## 范围
- 新增删除图书接口（如 DELETE /api/books/{id} 或等价设计），按图书 ID 删除
- 前端图书列表展示，并提供选择/删除操作入口，调用删除接口后刷新列表
- 后端在 / 托管静态页面，静态资源与 API 同端口 8080 提供
- 提供 GET /health 健康检查
- 删除不存在图书时返回明确错误（如 404），删除成功返回成功状态

## 不在范围
- 不引入独立前端工程与独立前端开发服务器/端口
- 不实现用户登录鉴权与权限控制
- 不实现图书编辑、批量删除、软删除与回收站
- 不引入数据库迁移与外部存储改造（沿用现有内存或既有存储方式）

## 非功能
- 使用 Go 标准库 net/http，不引入重型框架
- 接口返回 JSON，错误响应结构统一、状态码语义正确
- 删除操作需保证并发安全（对共享存储加锁）
- 前端页面为静态资源，无需构建步骤即可由后端直接托管

## 待决问题（确认时已接受）
- 图书标识使用自增整数 ID 还是字符串 ID，需与现有数据结构对齐
- 现有图书存储是内存切片还是已有持久化层，删除需按实际实现适配
- 删除成功后前端是整页刷新列表还是局部移除，需确认交互细节
- 是否需要删除前二次确认弹窗
