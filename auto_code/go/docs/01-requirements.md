# 图书管理服务（含删除图书与静态前端）需求说明

## 背景
当前工程为 Go 标准库 net/http 实现的图书服务（module `example.com/autocode`，go 1.22），已具备图书列表、创建、详情、删除、库存调整等 API 面。本次需求聚焦于「删除图书」能力的完整闭环：后端提供按 ID 删除图书的接口，前端页面可选择某一本图书并触发删除，删除后刷新列表；同时由后端托管静态页面，前端与 API 同端口访问。

> 说明：本文件为从零生成场景下的需求基线，按目标栈约定端口为 **8072**（基线约定），用户原始需求中提到的 8080 作为历史描述，实际以基线端口 8072 为准；前端访问地址为 `http://localhost:8072/`。

## 目标
- 提供删除图书的 HTTP 接口，支持按图书标识删除指定图书。
- 前端页面展示图书列表，可选择某一本图书并触发删除，后端执行删除并返回结果，前端刷新列表。
- 后端在 `/` 托管静态页面，静态资源与 API 同端口提供。
- 提供 `GET /health` 健康检查，返回 JSON `{"status":"ok"}`。
- 删除不存在图书返回明确错误（404），删除成功返回成功状态。

## 范围
### 后端
- 新增 `DELETE /api/books/{id}` 删除图书接口，按整数自增 ID 删除。
- 保留并实现图书列表、创建、详情、库存调整接口（与现有 API 面一致）。
- 内存存储 + `sync.RWMutex` 保证并发安全。
- 统一 JSON 错误响应结构。
- 静态页面托管：`GET /` 返回 `index.html`，静态资源（CSS/JS）由后端直接提供。
- CORS 允许 Vite 开发端口 5173/5174（便于本地调试）。

### 前端
- 单页静态页面（HTML + 原生 JS，无构建步骤），由后端托管。
- 图书列表展示（ID、标题、作者、库存等）。
- 每行提供「删除」按钮，点击后弹出二次确认，确认后调用 `DELETE /api/books/{id}`。
- 删除成功后局部移除该行或重新拉取列表刷新。
- 删除失败（如 404）给出提示信息。

## 非功能
- 仅使用 Go 标准库 `net/http`，不引入第三方 Web 框架。
- 接口返回 JSON，错误响应结构统一、状态码语义正确。
- 删除操作对共享存储加锁，保证并发安全。
- 前端为静态资源，无需构建步骤即可由后端直接托管。
- 服务默认监听 8072 端口。

## 不在范围
- 不引入独立前端工程与独立前端开发服务器/端口（Vite 仅用于可选调试）。
- 不实现用户登录鉴权与权限控制。
- 不实现图书编辑、批量删除、软删除与回收站。
- 不引入数据库迁移与外部存储改造（沿用内存存储）。

## 启动方式与访问地址（硬需求）
- 启动后端：在 `auto_code/go` 目录执行 `go run .`（或 `go build -o app . && ./app`）。
- 前端访问地址：`http://localhost:8072/`（由后端静态托管，无需单独启动前端）。
- 健康检查：`http://localhost:8072/health`。

## 假设
- 图书标识使用自增整数 ID。
- 存储为内存切片/映射，进程重启数据丢失。
- 删除成功后前端采用重新拉取列表方式刷新。
- 删除前需要二次确认弹窗。
