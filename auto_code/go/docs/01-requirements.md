# 总需求

## 背景
当前工程 `auto_code/go` 已存在一个基于 Go 标准库 `net/http` 的图书服务（`main.go`），已提供健康检查、图书列表、新增、详情、删除、库存调整等接口，并在 `/` 托管静态页面。用户希望明确现有功能、启动方式与前端访问地址，并确保「删除图书」能力完整可用：前端可选择某一本图书并调用后端完成删除。

## 目标
1. 明确并文档化现有已实现功能（健康检查、图书 CRUD 子集、静态页面托管）。
2. 提供并完善删除图书接口 `DELETE /api/books/{id}`，按图书 ID 删除指定图书。
3. 前端静态页面展示图书列表，支持选择某一本图书并触发删除，删除成功后刷新/移除列表项。
4. 明确启动方式与访问地址：后端监听 8080，前端页面通过 `http://localhost:8080/` 访问。

## 范围
- 删除图书接口：按整数自增 ID 删除，成功返回成功状态，图书不存在返回 404。
- 前端静态页面：图书列表、选择、删除按钮、删除前二次确认、删除后刷新列表。
- 后端在 `/` 托管静态资源，静态资源与 API 同端口提供。
- 提供 `GET /health` 返回 `{"status":"ok"}`。
- 统一 JSON 错误响应结构。

## 非功能
- 仅使用 Go 标准库 `net/http`，不引入第三方 Web 框架。
- 共享存储并发安全（读写锁保护）。
- 错误响应结构统一、HTTP 状态码语义正确。
- 前端为纯静态资源，无需构建步骤。
- 启用 CORS，允许 Vite 5173/5174 来源（便于后续独立前端调试）。

## 假设
- 图书 ID 为自增整数（与现有 `main.go` 中 `/api/books/{id}` 路由一致）。
- 存储为进程内内存切片，不引入数据库与迁移。
- 端口沿用现有实现（8080），基线约定端口 8072 作为可配置项保留说明。
