# 总需求

## 背景
当前工程 `auto_code/go` 已存在基于 Go 标准库 `net/http` 的图书服务骨架（Handler/Service/Repository 三层，内存存储），已提供图书列表、新增、详情、库存调整等接口，并由后端托管静态页面。用户需要在现有图书服务基础上补齐「删除图书」能力：前端页面可选择某一本图书并触发删除，后端执行删除并返回结果。

## 目标
- 提供删除图书的 HTTP 接口，按图书 ID 删除指定图书（`DELETE /api/books/{id}`）。
- 前端图书列表页展示图书，提供选择/删除操作入口，调用删除接口成功后刷新列表。
- 后端在 `/` 托管静态页面，静态资源与 API 同端口提供（基线端口 8072，兼容用户提到的 8080 访问诉求，见假设）。
- 提供 `GET /health` 健康检查，返回 JSON `{"status":"ok"}`。
- 删除不存在图书返回 404 明确错误；删除成功返回成功状态。
- 修复新增图书校验错误：图书 id 必须为大于 0 的整数（`VALIDATION_ERROR`）。

## 范围
- 后端：新增删除图书接口；统一错误响应结构；对共享内存存储加锁保证并发安全；静态页面托管。
- 前端：图书列表展示、单选选择、删除按钮、删除前二次确认弹窗、删除成功后刷新列表、错误提示展示。
- 健康检查接口。

## 不在范围
- 不引入独立前端工程与独立前端开发服务器/端口。
- 不实现用户登录鉴权与权限控制。
- 不实现图书编辑、批量删除、软删除与回收站。
- 不引入数据库迁移与外部存储改造（沿用内存存储）。

## 非功能
- 仅使用 Go 标准库 `net/http`，不引入第三方 Web 框架。
- 接口返回 JSON，错误响应结构统一、状态码语义正确。
- 删除操作对共享存储加锁，保证并发安全。
- 前端为静态资源，无需构建步骤即可由后端直接托管。
- 启用 CORS，允许 Vite 5173/5174 来源（便于本地调试）。

## 假设
- 图书标识为自增整数 ID（与现有 `internal/model/book.go` 对齐）。
- 存储为内存切片/映射，删除按 ID 适配现有 Repository 实现。
- 端口以基线 8072 为准；用户提到的 8080 视为历史描述，访问地址相应为 `http://localhost:8072/`。
- 删除成功后前端局部移除该行并重新拉取列表。
- 需要删除前二次确认弹窗。
